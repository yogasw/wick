4 · Child session disembunyikan dari daftar conversation

"Sub-agent itu conversation baru tapi type sub-agent, jadi ngak masuk di list?" — tepat, dan itu memang arah design induk.

Secara teknis: session penuh
  • • punya ChildSessionID, store, transcript, workspace sendiri
  • • bukan objek kelas dua
  • • di-link via parent_session_id + root_id
Secara tampilan: disembunyikan
  • • difilter dari daftar conversation
  • • muncul di rail session induknya
  • • GET /sessions perlu exclude parent_session_id IS NOT NULL
✗ Field type: subagent pada session. parent_session_id sudah cukup menentukan "ini anak" — dua sumber kebenaran bisa saling bertentangan.
Jaga: URL langsung ke child session (dibookmark) harus tetap bisa dibuka → redirect ke parent dengan rail terbuka pada anak itu. Jangan 404.
5 · Scoping config — berlapis, bukan pilih satu

"Enaknya config agent per apa — project, provider, atau global?" → berlapis, dan wick sudah punya lapisannya (project.Defaults, sessionoverride).

LevelIsiSiapaKenapa di situ
Global max_depth, budget/root, max_parallel, cap max_turns admin guardrail — user tak boleh menaikkan
Profil utama provider, model, system_prompt, default_max_turns, tag ACL, allow_take_over admin identitas role — reusable lintas project & conversation
Project roster profil aktif + override model pemilik project tim/repo beda butuh roster beda; project.Defaults sudah pola ini
Session override sekali pakai user eksperimen tanpa mengubah profil (sessionoverride)
Presedensi: session > project > profil > global-cap. Global selalu jadi plafon, bukan default yang bisa dilampaui.
✗ Per-provider. Provider adalah pilihan di dalam profil ("researcher pakai claude"). Kalau config per-provider: satu role tak bisa punya dua varian model, dan pindah provider = kehilangan seluruh setelan role.

Kenapa profil ini pembenaran terkuat untuk rail + interrupt
Boros turn. generate → nilai → ulang. Nested langsung banjir; kartu ringkas menyelamatkan main thread.
Output visual per turn. Main cuma perlu hasil final — percobaan tengah adalah kebisingan yang tepat untuk panel rail.
Sering dihentikan di tengah. "udah, yang kedua aja" = interaksi normal → menutup design induk §14.3.
Butuh koreksi manusia. "yang ketiga tapi lebih gelap" → menggeser usulan take-over ke per-profil.
biaya berlapis default_max_turns (profil) × cap n (tool). Tanpa keduanya, satu delegasi bisa membakar puluhan image call.
Sengaja ditolak
Satu rail tab per sub-agent — rail habis ruang. Satu tab + tree di panel.
Pane kiri / level-2 di SessionList (usulan versi pertama) — sidebar kiri adalah daftar conversation, dan sub-agent justru disembunyikan dari daftar itu (§4).
Reuse DetailView utuh — panel dapat rail bersarang di dalam rail (§2).
Field type: subagent — parent_session_id sudah cukup; dua sumber kebenaran bisa bertentangan (§4).
Config per-provider (§5) — satu role tak bisa punya dua varian model.
Agent menerbitkan profil persisten (§6) — privilege escalation lewat tag ACL.
Interrupt = error ke leader — memicu retry buta.
Hub SSE baru — /stream existing sudah broadcast lifecycle (design induk §8.3).
Menghapus nested view sepenuhnya — kartu ringkas di main thread tetap perlu, supaya transcript leader tetap jadi catatan audit yang utuh ("di sini dia delegasi, ini hasilnya").
